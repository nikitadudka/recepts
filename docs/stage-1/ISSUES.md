Версия **stage1-v1**, 22 октября 2026. Перед созданием через GitHub проверены Issues всех состояний и открытые PR репозитория: подходящих задач и активной реализации не найдено. Процесс [AGENT_WORKFLOW](../AGENT_WORKFLOW.md) предусматривает отдельные Issues; созданы шесть записей без новых labels/Projects, назначений людей и изменения настроек репозитория.

Все записи имеют статус **«Ожидает одобрения»** в описании. GitHub `open` означает открытую задачу, не разрешение разработки. Следующий ответственный — **владелец через Product Manager**. Требуется явное одобрение commit документационного PR + stage1-v1 и конкретных подзадач. Ни одна Issue не закрывается текущим документационным PR.

Полные цель, ценность, решение, компоненты, риски, приёмка и QA — в [BACKLOG](BACKLOG.md) и описаниях Issues. Последовательность ролей и R1–R5 — в [PLAN](PLAN.md). Точные контракты — в [TECHNICAL_SPEC](TECHNICAL_SPEC.md), состояния/макеты — в [MOBILE_UX_SPEC](MOBILE_UX_SPEC.md), проверки — в [QA_PLAN](QA_PLAN.md).

PM подготовил brief и границы, UX/UI получил задачу и подготовил предложение; Architect получил контекст для предварительного анализа, QA — для проверки критериев. Полный переход к Developer пока заблокирован отсутствием отдельного разрешения владельца. Одобрение фиксируется по форме AGENT_WORKFLOW в Issue и DECISIONS; после него PM указывает следующего исполнителя, а каждый PR связывается с Issue и версией разрешения.

Для составных A05/A06/A07 в одной Issue ведётся список малых PR; `Closes` используется только после завершения всего одобренного объёма. Обновление статуса требует факта передачи/результата, а не истечения времени. Не создавать повторную задачу с тем же ID в следующем чате: продолжать эти записи.
